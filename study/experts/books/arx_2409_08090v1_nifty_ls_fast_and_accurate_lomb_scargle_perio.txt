                                                                                                               ABSTRACT
                                                          We present nifty-ls, a software package for fast and accurate evaluation of the Lomb-Scargle
                                                       periodogram. nifty-ls leverages the fact that Lomb-Scargle can be computed using a non-uniform
                                                       FFT (NUFFT), which we evaluate with the Flatiron Institute NUFFT package (finufft). This
                                                       approach achieves a many-fold speedup over the Press & Rybicki (1989) method as implemented in
                                                       Astropy and is simultaneously many orders of magnitude more accurate. nifty-ls also supports fast
                                                       evaluation on GPUs via CUDA and integrates with the Astropy Lomb-Scargle interface. nifty-ls
                                                       is publicly available as open-source software.


                                                       Keywords: Astronomy software (1855) — Lomb-Scargle periodogram (1959) — GPU computing (1969)


                                                                                                             1. INTRODUCTION
                                                 The Lomb-Scargle periodogram is a widely-used analysis tool for astronomical time-series data1 (Lomb 1976; Scargle
                                               1982; c.f. VanderPlas 2018). However, its direct computation is prohibitively slow: for a number of observations Nd and
                                               number of periodogram frequencies Nf , the work has time complexity O(Nd Nf ). The popular Press & Rybicki (1989)
                                               method (hereafter PR89) addresses this by posing the computation as four weighted trigonometric sums solved with
                                               a pair of fast Fourier transforms (FFTs) on an equi-spaced grid. The unevenly sampled data points are interpolated
                                               to this grid by a process that PR89 call “extirpolation.” The trigonometric sums take the form:

  We evaluate the NUFFT with finufft, the Flatiron Institute NUFFT (Barnett et al. 2019; Barnett 2021). The
finufft approach is similar in spirit to PR89—upsample the data to a fine grid, perform an FFT, then correct with
a diagonal rescaling—but finufft has a near-optimal spreading kernel (an “exponential of semicircle”) that it uses
instead of extirpolation. Its width and fine grid size are carefully chosen to match the user tolerance ε, and manual
SIMD-vectorized piecewise polynomials makes kernel evaluation extremely fast. finufft also supports multi-threaded
CPU evaluation and GPU evaluation via CUDA (Shih et al. 2021), with best-in-class performance and accuracy.
  We implement this finufft-based Lomb-Scargle periodogram in the nifty-ls software package. nifty-ls is writ-
ten in Python, with some modules implemented using C++ and OpenMP for performance. It provides a backend
to the Astropy Lomb-Scargle interface, so code that uses Astropy can benefit with minimal changes (setting
method="fastnifty" in Astropy calls). nifty-ls is developed as open-source software on GitHub4 , with binary
distributions available on PyPI.

                                                                            2. RESULTS
  We characterize the performance and accuracy of nifty-ls in Fig. 1. We use nifty-ls version 1.0.1, finufft
version 2.3, and Astropy version 6.1.3. As a test dataset, we use a double-precision time series with Nd ∈ 102 , 106
and use the default Astropy Nf ≈ 12Nd . We use (up to) 16 cores of a Intel Xeon Ice Lake processor for the finufft
(CPU) backend and and 1 NVIDIA A100 GPU for the cufinufft (GPU) backend.

                                                                           2.1. Performance
  nifty-ls is several times faster than Astropy fast on using a single CPU thread, with speedups of 2× on small
transforms to 5× on large. This is seen in the left panel of Fig. 1. CPU multi-threading helps large transforms, yielding
a 11× speedup over Astropy, although the improvement is sub-linear in the number of threads (a well-known result
for FFTs, since the time is dominated by memory accesses). The performance can be summarized by around 107
output frequencies per second on the CPU, or 108 on the GPU. Additionally, nifty-ls exposes a batched processing
mode for sets of time series with the same observation times, which can more efficiently use CPU and GPU parallelism.
  Using the GPU via cufinufft, nifty-ls is 200× faster than Astropy for large Nd . For small Nd , the problem is
not large enough to overcome GPU overheads or saturate the GPU. Still, for Nd as small as 4000 there is a benefit
over finufft, which extends to smaller Nd for batched transforms.

  Our tests also suggest that the NUFFT approach is more efficient than a brute-force (i.e. quadratic complexity)
CUDA evaluation of Eqs. 1 in the style of Townsend (2010) and Gowanlock et al. (2021). The latter work reports a
single-object rate of about 2×107 frequencies per second on a P100 GPU, which is about the speed of our CPU version,
and several times slower than our GPU version even after accounting for the naive 2.4× performance advantage of the
A100.

                                                                2.2. Accuracy
   nifty-ls is many orders of magnitude more accurate than Astropy fast, using default settings for both. On this
dataset, it is conservatively 6 orders of magnitude better. This is shown in the right panel of Fig. 1. For each method,
the median and 99th percentile of the periodogram error distribution is shown. Furthermore, for Astropy, two cases
are considered. Internally, Astropy uses an FFT whose size is the next power of 2 above the specified oversampling
rate. A jump in FFT size typically yields an increase in accuracy. Thus, we expect the worst accuracy to be from the
largest Nf that does not yield such a jump. This is labeled “Astropy (worst case)” in the Figure. The case labeled
“Astropy” is the first Nf after such a jump.
   For Astropy in the baseline case, median errors are about 0.1%, while the 99th percentile error is a few percent
(with a few excursions to larger errors). In the worst case, however, the median error is typically 1% and the 99th
percentile is 10% to 100% or greater.
   nifty-ls demonstrates greater accuracy for both backends, with median relative errors of 10−11 to 10−8 , and 99th
percentile errors of 10−8 to 10−6 . We note that the condition number of the problem5 imples that errors in Eqs. 1
cannot in principle be smaller than O(Nf εmach ), where εmach is machine precision. For double precision, εmach ≈ 10−16 ,
so the minimum achievable error for a transform of length Nf = 105 is about 10−11 . Were we to use single precision,
with εmach ≈ 10−7 , the minimum achievable error would be quite large, about 10−2 . Hence, we restrict our tests to
double precision and recommend its use in large periodograms.
   Astropy has several parameters that can be tuned to yield more accurate results, but these come at the cost of
performance. Likewise, nifty-ls can produce lower-precision results slightly faster than reported above, but with
Nf ≈ 12Nd , the FFT time dominates over the spreading time.
   The reference result here is a direct evaluation of the trigonometric sums in Eqs. 1, using exact angle-sum trigonomet-
ric identities to accelerate the computation (a “phase winding” method). Using Astropy fast with “use fft=False”
(which does a brute-force evaluation) yields the same result.
   In summary, nifty-ls provides greater accuracy and speed than extirpolation-based methods, and thanks to its
Astropy integration and available binary distributions, has a low barrier to adoption. We hope that this will provide
an improved experience for users of the Lomb-Scargle periodogram.
